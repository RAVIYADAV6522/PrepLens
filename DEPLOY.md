# Deploying prepLens

Three services, all free or nearly free: MongoDB Atlas for data, Render for the
API, Vercel for the web app.

Everything in this file is a step only *you* can take — it needs accounts,
billing and a domain. The code is ready for all of it.

---

## 1 · Atlas (done)

The cluster exists. Two things to do before launch:

- **Rotate the database password.** It was pasted into a chat, so treat it as
  compromised: Atlas → Database Access → Edit → Edit Password, then update
  `MONGODB_URI` in `api/.env` and in Render.
- **Network access.** Render's outbound IPs change, so allow `0.0.0.0/0` and
  rely on the database user's credentials, or use Atlas's Render integration if
  you want it tighter.

Create the indexes once against production:

```bash
cd api
MONGODB_URI="<production uri>" npm run indexes
```

`autoIndex` is off in production on purpose — an index build on a populated
collection can block writes at an unpredictable moment.

## 2 · Google OAuth

Google Cloud Console → **APIs & Services → Credentials → Create credentials →
OAuth client ID → Web application**.

Authorised redirect URIs — add both:

```
http://localhost:4000/api/v1/auth/google/callback
https://api.preplens.app/api/v1/auth/google/callback
```

A mismatch here, down to the trailing slash, is the single most common OAuth
failure. The value must equal `API_URL` + `/api/v1/auth/google/callback`.

Then set `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` in `api/.env` and in
Render. Until they are set the API still boots and serves the whole public
archive — only sign-in returns 503. That is deliberate.

On the OAuth consent screen, set the app to **Internal** if NST uses Google
Workspace; otherwise **External** and add yourself as a test user until it is
verified.

## 3 · Render (the API)

Dashboard → **New → Blueprint** → point at this repository. `render.yaml` sets
everything except the secrets, which Render prompts for:

| Variable | Value |
|---|---|
| `MONGODB_URI` | the production connection string, ending `/preplens` |
| `FRONTEND_URL` | `https://preplens.app` — no trailing slash |
| `API_URL` | `https://api.preplens.app` |
| `GOOGLE_CLIENT_ID` / `_SECRET` | from step 2 |
| `SUPER_ADMIN_EMAILS` | your college address, so you are promoted on login |

`SESSION_SECRET` is generated by Render. Health checks hit `/healthz`, which
returns 503 when the database is unreachable — so a broken deploy fails instead
of going live looking healthy.

**The plan is `starter`, not `free`.** See the comment in `render.yaml`.

---

## 4 · Vercel (the web app)

Import the repository, then set **Root Directory** to `web`. Framework preset:
Vite. One environment variable:

| Variable | Value |
|---|---|
| `VITE_API_URL` | `https://api.preplens.app` |

`vercel.json` handles the rest: SPA rewrites, immutable caching for hashed
assets, and routing `/experience/:id` through `api/og.js` so shared links
preview with the company and role instead of a bare site name.

---

## 5 · The domain (the step that saves an evening)

Buy one domain and use two subdomains:

```
preplens.app       -> Vercel   (the web app)
api.preplens.app   -> Render   (the API)
```

They are then **same-site**, so the session cookie works with
`SameSite=Lax` — which is what `lib/cookies.js` already sets.

Splitting them across `preplens.vercel.app` and `preplens-api.onrender.com`
makes them cross-site, which forces `SameSite=None` and a weaker posture. If
you must ship without a domain, that is the one line to change.

## 6 · Before you announce it

- [ ] `npm test` passes against the production-shaped configuration
- [ ] `/healthz` returns 200 with `database.status: "ok"`
- [ ] Sign in with your college account; sign in with a personal Gmail and
      confirm you get the readable rejection, not a loop
- [ ] Submit one experience, retract it, publish it again
- [ ] Paste an experience link into WhatsApp and check the preview
- [ ] Open the site on a phone, signed out
- [ ] Set up an uptime check on `https://api.preplens.app/healthz`
- [ ] Add Sentry DSNs if you want error tracking beyond the logs
- [ ] ≥ 25 experiences published with recorded consent (`npm run consent -- --list`)

The last one is the real gate. Launching an empty archive spends the one
announcement you get.
